Projektübersicht

Dieses Projekt zeigt den Aufbau einer virtualisierten Netzwerkumgebung mit mehreren Linux- und Windows-Systemen. Ziel war es, sichere Kommunikation zwischen den Systemen zu ermöglichen sowie Remotezugriffe effizient und praxisnah umzusetzen. Der Fokus lag auf SSH-Authentifizierung, Netzwerkverständnis und der Nutzung eines modernen VPNs (Tailscale).

Ziele des Projekts

Setup

Virtualisierung: Oracle VM VirtualBox

  • Mehrere virtuelle Maschinen (Linux & Windows)
  • Gemeinsames internes Netzwerk zur Kommunikation
  • pfSense als Firewall und Router für das interne Netzwerk

Nach der Einrichtung von pfSense habe ich überprüft, welche Ports und welche WebGUI-Protokollversion verwendet werden, um sicheren Zugriff über den Browser zu gewährleisten.

SSH‑Konfiguration

Gemeinsame Einstellungen auf allen Systemen

Vor der eigentlichen SSH‑Konfiguration wurden alle Linux‑Distributionen aktualisiert und der SSH‑Dienst geprüft:

sudo systemctl status ssh
sudo systemctl enable ssh
sudo systemctl start ssh

Sicherheitsrelevante Einstellungen

  • PermitRootLogin no: Root‑Login deaktiviert
  • PubkeyAuthentication yes: Nur SSH‑Key‑Authentifizierung
  • PasswordAuthentication no: Passwort‑Login deaktiviert
  • MaxSessions 1: Nur eine aktive SSH‑Session pro Verbindung
  • Port 50000: Alternativer SSH‑Port zur Reduktion von Standard‑Scans

Hostnames (z. B. arch, debian, ubuntu-desktop, alma, win11) wurden zentral dokumentiert, um Verbindungen ohne IP‑Nachschlagen aufzubauen.

SSH unter Windows

  • Erstellung von SSH-Key-Paaren
  • Verteilung der Public Keys auf Linux-Systeme
  • Passwortlose Anmeldung, z. B. ssh arch von Windows 11

Netzwerk & Tailscale-Integration

Alle VMs wurden in dasselbe interne Netzwerk wie pfSense eingebunden (z. B. Intnet in VirtualBox).

Nach der Installation von Tailscale auf allen Systemen erfolgt die Anmeldung über einen Bestätigungslink, woraufhin die Systeme in der Tailscale-Liste erscheinen.

ACLs & SSH über Tailscale

  • Freischaltung aller relevanten Adressen
  • Meine Mailadresse als Quelle
  • Port 50000 für SSH aktiviert

SSH-Verbindung über Tailscale (nicht Standardport 22):

ssh -p 50000 mario@100.x.x.x
